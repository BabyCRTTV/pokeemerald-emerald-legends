# Native seasonal encounters / DexNav preview

After the normal Debug ROM/ELF build, run `python3 tools/legends/native_seasonal_encounters_qa/run.py` with the ARM tools, mGBA 0.10.2 development library and Pillow installed. The mGBA CI job reuses its existing build for this step.

Nineteen controlled cases cover Routes 101–104 in all seasons, all-unseen and all-seen land-roster states, and Route 104's southern half. Each creates 256 actual wild Pokémon with the native generator and checks species/level membership, committed-vs-pending tables, the displayed unique land roster, original icon image pointers/VRAM animation frames, black-only silhouette palettes, unchanged known palettes, an unseen A-button lock, UI closure and protected state. The source/C regressions separately establish the original residents, precise 70/20/10 base odds, levels/rates, unavailable prior-season DexNav targets and unrelated-map fallback behavior.

A temporary callback uses controlled flags/vars in an instrumented copy of the compiled Legends Debug ROM. Screenshots are real native mGBA video-buffer pixels. This does not establish natural progression, full DexNav hunts, historical-save migration, Release interaction or Pizza Boy coverage. ROMs/ELFs/saves are never artifact paths; the private ROM is deleted even on failure. Only PNG/JSON/logs are uploaded. Keep the trial on the draft branch until the owner approves the actual-game preview and encounter roster.

The initial run passed both game builds and ordinary native checks but the preview checker referenced an inlined private function. The checker now uses only address-taken GUI task/static state symbols and presses real A to test unseen rejection. DexNav level lookup receives an executable shipped-C regression; no game function is made public or marked noinline for instrumentation.
