# Shared native and patch builds — 28 October 2026

Model: GPT-6 (Codex) | Reasoning: compile each variant once, bind native/decoder results to those immutable files and transfer only safe patch payloads to publication.

Baseline: completed seasonal parallelism and published v0.0.75 at `72bf6b8c62ac6b35bde44c6b7ac6b93f06d8ad3e`. Owner authorized the second optimization: eliminate repeated compilation between native QA and patch generation. Game code, assets/maps, saves, VERSION and seasonal worker logic remain unchanged. This does not implement atomic frontend/site promotion or candidate-to-production evidence reuse.

## Execution and gates

- `build-release-patch.yml` is the only automatic entry point for the combined union of game/build/QA inputs. It calls the native workflow at the same commit. `mgba-gameplay-qa.yml` remains callable and manually available; it no longer independently auto-builds the same revision. Distinct concurrency groups avoid caller/callee cancellation; obsolete PRs cancel while master commits retain their verification gates.
- One read-only job compiles Debug and Release once, retaining separate ROM/ELF files on its private runner. Makefile has separate variant object directories and ELF names. A nonce-bound manifest records source commit/tree, input fingerprint and hashes of all four files. No full ROM, ELF or battery save is transferred or cached.
- All original native commands and assertions remain. Release compilation moves ahead of QA so canonical-base construction, Floating IPS reconstruction and the shipped browser decoder can execute alongside native tests. The patch subprocess owns separate private directories, caps make parallelism at two and has a 20-minute process-group deadline. Its nonce-bound result is joined even after an ordinary native failure; cancellation does not wait for it. Job cleanup terminates remaining processes.
- Final verification checks that all four build hashes are unchanged, all twelve native receipts identify the corresponding Debug/Release ROM, and both independent patch decoders reproduce those exact targets from the canonical clean Emerald base. Missing/failed/mismatched receipts reject the job. Seasonal QA retains all 288 cases / 73,728 creations and the first optimization's worker controls.
- Only after all checks pass is a five-file `legends-candidate-patches` artifact retained: two BPS files, SHA256SUMS.txt, browser-decoder-verification.json and verification.json, now at the artifact root. Finalization rejects unexpected files before upload. Native captures/diagnostics retain the `legends-mgba-gameplay` artifact name and add only top-level shared-build JSON/logs.
- A separate write-enabled publication job downloads only that safe payload from the same workflow run. Job outputs pin the manifest SHA256, source commit and fingerprint. The publisher verifies payload hashes, BPS CRCs, VERSION and current tracked inputs before staging, and checks again after each rebase/push retry. It permits only existing bot-managed `docs/downloads/` and Android/Windows version-manifest changes; any other newer tracked change conservatively blocks the older publisher. Existing owner maps and source are never overwritten. An unchanged patch pair is a verified no-op.

This removes the second full Debug/Release compilation pair per candidate or production phase. It reduces duplicate runner work and lets a failed publication retry without recompiling. It does not promise a fixed wall-time reduction: shared-runner CPU contention, dependency setup and canonical-base work vary. Native and decoder gates remain mandatory; PR artifacts cannot trigger the write-enabled publisher.
